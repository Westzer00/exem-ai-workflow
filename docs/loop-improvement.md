# LOOP 입출력 개선 — 문제·설계·검증

## 문제
기존 반복 실행은 하위 그래프의 대표 출력 하나를 중심으로 값을 전달했습니다. 생성 초안과 검수 결과를 다음 회차에 각각 활용하기 어려웠습니다.

## 구현한 방향
- 입력 바인딩으로 반복 진입 전에 입력을 결정하고 내부에서 공통 참조
- 출력 바인딩으로 필요한 내부 노드 결과를 별칭에 연결
- 직전 성공 회차의 별칭별 결과를 이전 회차 상태로 전달
- 회차별 결과·최종 결과를 따로 보관하고 지정한 별칭으로 종료 조건 평가
- 기존 출력과 반복 상한의 호환성을 고려하고 잘못된 경로·실행 실패를 구분
- 중첩 값의 변경이 앞선 회차 기록에 영향을 주지 않도록 상태를 분리

## 설계 판단
내부 노드 ID를 외부 공개 계약으로 직접 노출하지 않고 **출력 별칭**을 사용했습니다. 팀의 반복 생성·검수 흐름에서는 앞선 초안과 검수 판단을 서로 구분해 활용할 수 있어야 했기 때문입니다.

## 공개 예제와 실제 플랫폼의 차이
이 저장소의 독립 예제는 명시적 입력·출력 경로, 이전 회차의 값, 단일 종료 조건, 중첩 값 복사와 오류 처리를 보여줍니다. 실제 플랫폼의 더 넓은 JSON 입력 계약, 노드 종류별 공개 출력 검증, 기존 워크플로우 호환성, skipped/null 처리와 **새 설정을 편집하는 제품 UI 연동**까지 전부 재현한 것은 아닙니다.

개발 배분 문서에서 개인 LOOP 기능 담당이 확인됐고, 백업된 Python 작업본에 실행 로직과 관련 테스트가 있습니다. 설계 목표와 제품 배포 완료는 별개입니다.
